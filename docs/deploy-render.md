# Deploy the demo on Render

This is a free [Render](https://render.com) Web Service for one classroom demo. It uses the Blueprint in `render.yaml`. There is no database, disk, or paid add-on. Python is pinned to 3.12.8 (`PYTHON_VERSION` and `.python-version`), the same 3.12 line the app is written for.

## One-click Blueprint

1. Sign in to the Render Dashboard. The first time, authorize Render's GitHub app for `Haim-Barby/ZooMoodle`.
2. Choose **New** → **Blueprint**.
3. Select this repository. Render reads `render.yaml` from `main`.
4. Apply the Blueprint. The service name is `zoomoodle`. It builds with `pip install -r requirements.txt` and starts one uvicorn worker on `$PORT`.
5. Wait until the deploy is live. Open `https://<service>.onrender.com/api/health`. A healthy process returns `200` and `{"status":"ok",...}` with no secret in the body.

`autoDeploy` follows `main`. A push to `main` redeploys. The public URL is Render's `RENDER_EXTERNAL_URL` (usually `https://zoomoodle.onrender.com`, or that name plus a suffix if it is taken). Student join links use that https origin.

## Lecturer token

`ZOOMODLE_MASTER_SECRET` and `ZOOMODLE_LECTURER_TOKEN` are generated by Render. They are not in git and the process does not print them.

To unlock the lecturer page: Render Dashboard → this service → **Environment** → reveal `ZOOMODLE_LECTURER_TOKEN`. Copy it into the lecturer page. Do not paste it into chat, issues, or commits.

If either variable is empty, the process refuses to start and names the missing variable. Local runs are unchanged: an empty `.env` still generates a one-process secret and prints the lecturer token once.

## Before class

The free plan spins the service down after about 15 minutes with no requests. The next request is a cold start and can take up to about a minute.

A few minutes before class, open `/api/health` and leave a tab open so the process stays up. Open the room only after that check succeeds. Rooms live in memory: a restart, a redeploy, or a spin-down erases them. Export the attendance sheet before you finish.

## What this deploy does not prove

`ZOOMODLE_ALLOWED_SUBNETS` is empty, so the campus subnet check is off. It is not verified on Render.

Phones need HTTPS for the microphone. Render serves HTTPS. Real speaker-to-phone audio on that URL has not been tried; use the on-screen code if listening fails, and record that separately.

No LLM key is configured. Test connection asks you to enter an API key first. A lesson or homework run without a key returns a configuration error and does not invent a report. A key typed into the lecturer page stays in that process only and disappears on restart. The Blueprint does not ask for `LLM_*` variables.

`FORWARDED_ALLOW_IPS=*` is set because only Render's proxy can reach the process. Uvicorn then treats the first `X-Forwarded-For` hop as the client and `X-Forwarded-Proto` as `https`. `ZOOMODLE_TRUSTED_PROXIES` still includes loopback, plus private ranges for Render's own proxy. The local default remains loopback, so a direct client cannot spoof a campus address. Device checks use the phone's key, not the shared proxy address.
